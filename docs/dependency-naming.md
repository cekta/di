# Имена зависимостей

Каждая зависимость в конфигурации DI идентифицируется по уникальному **имени**. Знание правил
формирования этих имён — ключ к правильной настройке `params` и `alias`.

## Формирование имени

Имя зависимости строится из сигнатуры конструктора потребляющего класса. Разберём основные случаи
на примере:

```php
<?php
namespace App;

class Example
{
    public function __construct(
        string $locale,        // примитивный тип
        Logger $logger,        // тип-класс
        string|Logger $mix,    // объединённый тип
        ?Logger $optional,     // nullable
        Logger ...$logs,       // вариативный аргумент
    ) {}
}
```

Для каждого аргумента генерируются два имени — **глобальное** и **локальное**:

| Аргумент | Глобальное имя | Локальное имя |
|----------|----------------|---------------|
| `string $locale` | `"locale"` | `App\Example::class . '$locale'` |
| `Logger $logger` | `"App\Logger"` | `App\Example::class . '$logger'` |
| `string\|Logger $mix` | `"string\|App\Logger"` | `App\Example::class . '$mix'` |
| `?Logger $optional` | `"?App\Logger"` | `App\Example::class . '$optional'` |
| `Logger ...$logs` | `"...App\Logger"` | `'...' . App\Example::class . '$logs'` |

## Глобальное или локальное?

### Глобальное имя

Применяется ко **всем** потребителям сразу. Удобно для привязки интерфейсов и общих параметров:

```php
'params' => [
    'locale' => 'ru_RU',  // все locale-параметры во всём проекте
],
'alias' => [
    Logger::class => Monolog\Logger::class,  // все, кто просит Logger, получат Monolog
],
```

### Локальное имя

Применяется **точечно**, только к одному аргументу одного класса. Удобно для переопределения:

```php
'params' => [
    App\Example::class . '$locale' => 'en_GB',  // только для Example::$locale
],
```

### Приоритет имён

Локальное имя имеет **больший вес** над глобальным. Если для одного аргумента определены оба имени —
используется локальное, а глобальное игнорируется для данного потребителя:

```php
'params' => [
    'locale' => 'ru_RU',                             // глобальное: все получают 'ru_RU'
    App\Example::class . '$locale' => 'en_GB',       // локальное: Example получает 'en_GB'
    App\Other::class . '$locale' => 'fr_FR',         // локальное: Other получает 'fr_FR'
],
```

В этом примере:

| Потребитель     | Использованное значение | Причина                            |
|-----------------|------------------------|-----------------------------------|
| `Example`       | `en_GB`                | локальное имя переопределяет      |
| `Other`         | `fr_FR`                | локальное имя переопределяет      |
| остальные       | `ru_RU`                | локальное не задано, используется |

## Приоритет конфигурации

Одна и таже зависимость, может быть разрешна 3 разными способами

1. params
2. alias
3. Значение по умолчанию для аргумента (если есть).
4. autowiring - внедрение на основе класса и конструктора

Также params и alias имеют локальные и глобалные имена.

Что будет если одна завимость может быть разрешна всеми доступными способами ?

Какой будет использоваться ?

Вот приоритет конфигурации:

1. params с локальным именем.
2. alias с локальным именем.
3. params с глобальным именем.
4. alias с локальным именем.
5. значение по умолчанию (если задано).
6. autowiring если возможно.

Выше важней, во время  [генерации контейнера](generate.md) используется первый доступный способ и сохраняется.
